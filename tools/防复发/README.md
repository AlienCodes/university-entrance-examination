# 防复发机制（铁律 16，用户 2026-10-23）

目标：踩过的坑不靠记性防，靠程序保证不再犯；方法每一批都进化。

| 部件 | 文件 | 什么时候跑 | 拦什么 |
|---|---|---|---|
| 踩坑登记 | `踩坑登记.json` | — | CLAUDE.md 踩坑表每一行：阶段、哪段程序拦住（附代码出处）、双向验证命令、状态、缺口 |
| 防复发自检 | `防复发自检.py` | **每次提交前自动**（`.githooks/pre-commit`，约 0.5 秒） | 表里有没登记的行；新坑（72 起）没带双向验证；没有测试的旧坑变多（基线只许降）；上一批没复盘就开新批次 |
| 双向验证 | `防复发自检.py --测试`（各条命令在登记表里，`验证/` 下是新写的） | 改了任何检查程序后、每批开工前 | 故意把错误放回去，检查必须报出来；修好的版本必须 0 |
| 复盘统计 | `复盘统计.py <项目> --since …` | 每批发布后 | 程序数返工：同一篇音频生成几次、截图登记改几次、引擎中途改几次 |
| 复盘记录 | `方法进化记录.md` | 每批发布后写“## 复盘 <项目> <批次>” | 上一批不复盘，下一批（.github/*-render.txt 换新标签）提交不上 |

## 新坑的提交规矩

一条新坑必须**同一次提交**带齐：① 检查程序（自动跑在流水线里）② 双向验证命令（埋雷能报出、修好为 0）③ `踩坑登记.json` 条目 ④ CLAUDE.md 踩坑表一行。
缺任何一样，提交前钩子拦下。补检查时同一类坑**所有项目一起查**（规则只写一处，如 `tools/text_rules.py`）。

## 启用

新开会话时 `.claude/settings.json` 的 SessionStart 钩子自动执行 `git config core.hooksPath .githooks`。手动：`git config core.hooksPath .githooks`。
