# 原文与ASR词锚对齐

`原文对齐.py` 从全年译注草稿、逐词ASR和原音清单生成精听输入草稿。所有时刻保持canonical WAV的绝对秒数；音轨制作时另外传入 `--original` 并复核完整SHA256。工具不裁音、不改译文、不登记approved。

```bash
python 专八/听力/批量/tools/原文对齐.py 2009 2010 2011
python 专八/听力/批量/tools/原文对齐自检.py
```

默认读取 `译注草稿/<year>.json`、`预处理/<year>/识别.json`、`原音准备.json` 和存在的 `ASR核验.json`。元数据里的canonical音源SHA及ASR文件SHA必须一致；缺少元数据会明确留待核。识别的词尾本身若由模型估计，报告保留其 `word_end_estimate_seconds`，不能把候选误称为人工测得的声学边界。

对所有单元共同匹配单调词序。规范化仅含明确的数词、列出的缩写、OK/Okay、Dr/Doctor、收缩形式和大小写/重音差异。数词、缩写或收缩形式字面不同仍逐条写报告；不对实词做模糊拼写匹配。不能将can当cannot，不把没有识别出来的词按句长补时。多个原文字词对应一个ASR条目时共享该条目的完整真实时刻，不假定词内分界。

每句必须有句首词和句尾词的实际ASR锚才能导出。句内缺词保留在 `alignment.missing`，并阻断正式审校；词时刻只包括真实已绑定的部分。边界缺锚的整个单元放入 `核验/原文对齐/<year>/未导出单元/`，其中空时刻明确表示未知，不能送入制作器。已由本工具生成的旧draft会在新的对齐失败后从可制作目录移除，已审校或其他来源的输入会拒绝覆盖。

`精听数据/` 仅写接口合格的draft。`review.status`永远是draft，每个单元保留原有待核项并追加机器核验要求。全部差异、原文字词覆盖率和ASR未覆盖候选区间位于各年 `对齐报告.json`；未覆盖ASR可能是未录入的正式说明、原文漏句、模型重复或错识别，程序不擅自判断它是语音还是静音。音轨模块之后才可以检查并删除安全的句间纯静音。

正式说明由译注草稿的units/sentences原样加入，按录音顺序重跑即可；对齐器无固定正文起点，不会因新增说明沿用旧时间。单元ID与原有精听接口一致。窗口首尾默认各留0.12秒，是固定留白，不参与词时刻推算。通过 `--audio-template` 指定可移植相对路径；数据不写本机私有绝对音源路径。

## 有证据的人工映射

可通过 `--decisions '核验/原文对齐/{year}/人工裁定.json'` 提供局部裁定。每条必须绑定准确的原文字符、连续的真实ASR词下标、原始ASR文字和证据；不接收凭空秒数。更改源文、ASR或音源后不符的裁定会拒绝沿用。示意结构如下（下标须从实际报告填写，不能复制示意值）：

```json
{
  "year": 2011,
  "source_sha256": "canonical WAV的SHA256",
  "asr_sha256": "识别.json的SHA256",
  "bindings": [
    {
      "unit": "2011-B2",
      "sentence": 5,
      "char": [67, 74],
      "text": "Krashen",
      "asr_indices": [1234],
      "asr_text": ["Crashen."],
      "evidence": "此处填写实际页图、原音复听或局部识别证据"
    }
  ]
}
```

裁定不抹去机器最初发现的差异，另存 `human_decisions`，便于区分程序判断与人工证据。人工裁定也不能颠倒词序或抢占别句已绑定的词锚。整个单元仍需后续源文、译注、音轨、画面审核后才可正式登记。

## 正反例

`原文对齐自检.py` 使用2009、2010、2011讲座开头各两句与实际逐词ASR做正例。相同音频故意删除整句、交换句序或将morning改成evening均须失败。另检查cannot/can、不同数字不能误配；数字等价也须保留差异。自检不生成生产音频时刻，记录位于 `核验/原文对齐/正反例自检.json`。
