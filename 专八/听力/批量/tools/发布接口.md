# 专八历年视频的渲染与发布接口

入口：`.github/tem8-listening-history-render.json`。只在专用工作分支推送此文件触发，不改旧2025发布清单。唯一渲染矩阵合并考试与精听，最多20个任务；发布任务只续收、验证和打包，不调用生成程序。

## 启动清单

```json
{
  "mode": "sample",
  "sample_id": "trial-1",
  "stage": "review",
  "exam": [2009],
  "intensive": ["2009-A"],
  "render": true,
  "collect_runs": [],
  "reuse_releases": {"exam": [], "intensive": []}
}
```

- `mode=sample`使用独立样片Release：`tem8-listening-exam-sample-trial-1`与`tem8-listening-intensive-sample-trial-1`，不宣称全批。
- `stage=review`只运行原声预检、分屏和完整截图，把实际PNG、输入与机械报告存到`tem8-listening-review-2009-2024`，不编码正式视频。
- 实际看过截图并补齐登记后，改`stage=render`。任何图片内容或数量不一致都停止，不能自动批准未知截图。
- `render=false`不启动编码任务，只汇集已有成功结果。也可给`render_exam`和`render_intensive`指定本次只重做哪些失败项；它们必须是目标清单的子集。默认还会检测成功存档，输入指纹和服务器视频摘要一致的跳过编码。
- `collect_runs`指定此前Actions运行号，收其未过期artifact；`reuse_releases`可指定此前正式/样片Release，仍须有匹配当前输入指纹的成品及核验包。过期artifact不是唯一恢复来源。
- `force_render=true`仅用于明确需要重做相同输入的情况；通常不设置。改名或发布问题只改发布。

完整模式`mode=complete`必须同时满足`批量/全批清单.json`：

```json
{
  "status":"approved",
  "cancelled_years":[2020],
  "exam":[2009,2010,2011,2012,2013,2014,2015,2016,2017,2018,2019,2021,2022,2023,2024],
  "intensive":["实际核定的全部单元ID，不能使用这条示例"]
}
```

完整考试恰好实际15年；精听与核定单元清单精确一致且覆盖这15年。任何一类缺项都不会开始更新正式Release。正式目标为：

- `tem8-listening-exam-2009-2024`
- `tem8-listening-intensive-2009-2024`

## 完整15套考试先行发布

独立工作流`.github/workflows/publish-tem8-complete-exams.yml`只在专用分支`codex/tem8-listening-2009-2024`推送`.github/tem8-listening-exam-publish.json`时触发。它是单独的发布任务，使用独立并发组和仓库内置`GITHUB_TOKEN`，不等待主工作流的精听任务。控制文件在考试缓存迁移10套、修复5套全部核验成功后再创建或更新：

```json
{
  "mode": "complete_exam",
  "stage": "render",
  "exam": [2009,2010,2011,2012,2013,2014,2015,2016,2017,2018,2019,2021,2022,2023,2024],
  "intensive": [],
  "render": false,
  "collect_runs": [],
  "reuse_releases": {"exam": []}
}
```

`load_control`必须从上述独立路径加载；此工作流拒绝`sample`及`complete`模式。`complete_exam`严格要求实际15年、空精听清单、`stage=render`和布尔值`render=false`。这里的`stage`表示使用正式成品门禁，不启动编码；没有NLP、音频准备或视频生成步骤，也不会改动主渲染工作流的指纹。

工作流直接调用`pub.publish(c, art, out)`，先续收`tem8-listening-render-cache-2009-2024`及可选`collect_runs`/`reuse_releases.exam`中的已核成品。15套当前审核指纹的MP4与核验包必须全部齐全且通过检查，才开始更新正式考试Release `tem8-listening-exam-2009-2024`；精听Release按独立进度发布。打包、上传、服务器摘要与中文ZIP逐成员回下载核验沿用同一发布器，审计文件另存本次Actions artifact。缺成品或审核过期时失败退出，补齐后更新控制文件重试即可，不重新渲染视频。

## 两道审核登记

登记文件`批量/审核登记.json`：`{"entries":{"exam:2009":{...},"intensive:2009-A":{...}}}`。

1. 原卷、解析原文、录音及译注核对后，运行`发布汇集.py candidate exam 2009`或`candidate intensive 2009-A`得到待审项。实际审过后改`status=approved`，`evidence`写真实审校记录（至少10字）。不要批量填假审批。
2. 先跑`stage=review`或相同环境的本地预检。实际看过样片/新情况并确认所有机械关卡后，用`candidate KIND ID --work 工作目录`得到包含完整PNG摘要的登记项，保留真实证据，放回登记文件，再运行`stage=render`。

登记绑定实际输入JSON、原声准备脚本、适配器/共享引擎、字体/样式/重要配置及固定环境工作流的SHA；任一变化需要重新核对。图像检查使用完整PNG SHA的多重集合，允许绝对字体路径引起的HTML指纹文件名差异，但不允许图片内容或数量变化。两端仍须同样的浏览器/字体配置；本机不同环境时，应先在线出待审图，不能猜测登记。

精听自己的`review.status/content_sha256`和`approved-screens.json`门禁同时保留，外部登记不替代它们。在线`approve`动作只在完整图片与实际已审登记一致后执行，并引用真实登记的`evidence`。

常用命令：

```bash
python 专八/听力/批量/tools/发布汇集.py --自检
python 专八/听力/批量/tools/发布汇集.py candidate exam 2009
python 专八/听力/批量/tools/发布汇集.py gate exam 2009 --work 工作目录
python 专八/听力/批量/tools/发布汇集.py matrix
python 专八/听力/批量/tools/发布汇集.py publish --art art --out release-out
```

`candidate`只生成待审内容，不修改登记文件、不自动批准。

## 成果与续接

每个叶任务通过独立核验后，立即把MP4和包含实际已审PNG、源输入、音频来源、最终分屏方案、timings、meta及全部核查JSON的核验包保存到`tem8-listening-render-cache-2009-2024`。缓存资产名同时含输入指纹和MP4 SHA，旧版本不会因新的同名任务丢失。Actions artifact只是方便汇集的另一副本，上传失败不会抹掉已成功的持久存档。

正式汇集先核全部目标齐全、审核未过期、成品SHA与报告一致，再发布两种视频。视频资产使用ASCII名称，中文名写入标签、文件名对照表与ZIP；ZIP_STORED、不压缩、固定时间戳、中文UTF8标记，每包不超过1.8GiB。相同摘要资产保留不重传，仅标签有变时只改标签。

正式ZIP逐包从Release回下载，核整包SHA、CRC、每个MP4 SHA、中文名/顺序/时间戳/压缩方式，再持久上传`发布回下载核验.json`。发布失败可以用`render=false`重跑汇集，不重做已核视频。

旧2025的输入、分段视频及旧发布清单不参与本流程修改。
