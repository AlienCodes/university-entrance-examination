此工具只把已经通过、且旧新渲染结果完全等价的考试缓存移到新审批指纹，保持原MP4字节不变。它不调用视频/音轨/截图生成程序，也不改正式渲染工作流或发布门禁。

允许年份固定为2009、2012、2013、2014、2015、2018、2021、2022、2023、2024。2010、2011、2016、2017、2019无条件拒绝迁移，必须重编码。

`plan`只读旧缓存并输出待根审查的候选与实测依据，不写审核登记、不上传、不创建触发控制文件：

```sh
python3 专八/听力/批量/tools/迁移考试缓存.py plan --years 2009 --out /tmp/tem8-exam-migration-plan
```

默认旧审批来自`核验/分页短tick修复/旧登记/<year>.json`。`--old-registry`也接受完整历史审核登记JSON；`--source`可直接使用一份已经下载完整的旧stage，但只允许指定一年。下载得到的MP4/evidence逐年放在临时目录，完成即清理。

正式控制文件为`.github/tem8-listening-exam-cache-migration.json`，仅根审查代码、冻结等价证明、新registry与对应旧成品后创建并提交；当前实现没有创建该文件。字段如下，所有SHA必须从当前文件/真实旧cache取得，不能把占位内容提交：

```json
{
  "schema": 1,
  "status": "approved",
  "branch": "codex/tem8-listening-2009-2024",
  "repository": "AlienCodes/university-entrance-examination",
  "target_release": "tem8-listening-render-cache-2009-2024",
  "certificate": "专八/听力/批量/核验/分页短tick修复/15年状态与PNG等价证明.json",

  "registry_sha256": "填写提交时审核登记.json的64位SHA256",
  "root_review_sha256": "填写root-登记刷新.json的64位SHA256",
  "years": [2009],
  "old_fingerprints": {"2009": "填写该年真实旧审批指纹"},
  "old_mp4_sha256": {"2009": "填写该年真实旧MP4或Release服务器digest的SHA256部分"},
  "evidence": "根实际核查后填写批准理由，至少十字。"
}
```

一次最多列入上述十年，可列其中的子集续接。新工作流`migrate-tem8-exam-cache.yml`只由该控制文件在已审分支的push触发，单job串行处理全部所列年份，使用GITHUB_TOKEN持久保存到既有cache Release。新控制、代码、证据和registry都必须已提交；run拒绝相关工作树脏改，以确保`revalidated_commit`真实对应所验字节。

每年先下载旧MP4与evidence，核GitHub服务器SHA/字节数、ZIP CRC，再执行原`pub.validate_stage`；随后同时核以下证据：

- 当前输入SHA与旧registry完全相同，渲染依赖集合相同，唯一变化为冻结旧新SHA的`考试视频.py`。
- certificate本年safe、old/new完整state/帧表/逐state HTML/音频调用契约完全相同；音频、编码、核验和HTML函数AST独立重算，与冻结证据一致。
- cache真实`帧表.json`逐frame与certificate对应。local key与runner key可以不同，工具保留真实online key，不用local key删图或替换图片。
- 全部实际PNG的SHA多重集与旧、新registry相同；帧表可达图片集合、逐帧图片字节多重集完整保留。
- 原完整排版/成品报告无错误且非草稿/样片，旧报告里的纸面、时间轴、adapter、base来源指纹真实对应旧生成版本。
- 根`root-登记刷新.json`明确批准同一old/new fp与certificate、无新图、无删图、无需重编码；control同时绑定当前registry、根批准文件及原MP4 SHA。

迁移stage保存旧meta与旧registry原字节到`evidence/审批迁移/`，其余旧报告、截图和来源字节原样保留。为兼容原生产验证，固定`evidence/审核登记.json`入口替换为根批准的新registry。新meta仍保留原`source_commit`、`run_id`和真实旧报告，另写`current_registry`、新approval fp、`revalidated_commit`、新run id及显式`approval_migration`说明。MP4文件名资产指纹可更新，MP4字节、大小、SHA不变。

`pub.store_stage`按新fp保存MP4与完整evidence ZIP；随后再次核服务端资产SHA/大小。整批迁移摘要也持久保存到cache Release，状态明确为“所选无变化考试缓存迁移”，不声称全批视频已完成。Actions artifact仅作附加诊断。
