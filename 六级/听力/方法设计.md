# 六级听力 60 个视频：方法设计（2026-11-04）

老师要的：30 套六级听力（2018-12 至 2026-06），每套两个视频。
- **听力练习视频（30 个）**：与专八 2025“视频版真题考试”一模一样，白底黑字考卷样式。原音一刀不剪，画面跟着录音切换，倒计时按实测停顿逐秒走，考试中绝不出现答案，最后两屏给参考答案。
- **原文精读视频（30 个）**：与专八“听力原文精读”的做法相同（一屏一句英文 + 中文翻译 + 生词卡，声音用原音，长等待压到 2 秒），**画面用六级黑板主题**（老师 2026-11-04）。
- **文字**：transcripts（otter）当底稿，解析里的听力原文用来给 transcripts 挑错（老师 2026-11-04）。逐词时间由程序对录音算（transcripts 只精确到段落、到秒）。

## 一、流水线（每段在哪跑、谁拦住）

| 段 | 做什么 | 在哪 | 程序检查（出错即停，一次列全） |
|---|---|---|---|
| 0 清点 | 30 音频 ↔ 30 transcripts 按文件名配对；内层 zip 取 30 套真题 + 解析 | Actions `cet6-listening-materials.yml` → Release `6-listening-test` | 30 套无多无少；121 个文件 sha256 与仓库 `原始材料/SHA256SUMS` 逐个相同；下载回来再核 |
| 1 识别 + OCR | parakeet 逐词时间（照用 `专八/听力/tools/识别对齐.py`）；解析里“听力原文”那几页 tesseract 300 dpi OCR（7 套有文字层直接取） | Actions，30 套一套一台，结果提交到 `六级/听力/<套>/` | 每套识别词数、静音段、OCR 页都落盘；缺一样就停 |
| 2 文本定稿 | transcripts × 解析原文 × parakeet 三方逐词对齐：原文与 parakeet 一致而 transcripts 不同 → 按原文改；transcripts 与 parakeet 一致而原文不同 → OCR 错，保留；三方都不同 → 待核 | 本机（程序，几秒一套） | 每套差异表（分类计数）；待核的一次全部列出，只有这些交模型看 |
| 3 题目 + 答案 | 选项取真题文字层（2026-06 用仓库 `六级/真题/` 的 .txt）；题干取定稿 transcripts 的念题；答案取解析 | 本机程序 | 每套恰好 25 题 × 4 选项；题号连续；答案 25 个都在 A—D；选项与原卷逐字相同 |
| 4 时间轴 | 锚点（Section A/B/C、Conversation/Passage/Recording、Questions x to y、Question n、题后停顿）在识别结果里找 | 本机程序（几秒） | 踩坑 77：每个锚点恰好一处、全部按考试顺序递增、题后停顿个数 = 题数；静音终点取“能量终点”与“下一词开口”较早者 |
| 5 截图 + 视频 + 核查 | 每个画面状态一张 4K 截图 → 视频 → 成品核查 | Actions，30 套各一台 | 照用专八引擎：每张截图排版检查 + 题间空隙（铁律 19）+ CDP 字体回退 + 彩色像素 + 答案泄露；成品分辨率、恒定帧率、声画等长、开头 1.5 秒 / 结尾 ≥2 秒静音、整体响度、抽帧与截图一致 |
| 6 发布 | 60 个 mp4 发一个 Release | Actions | Python zipfile / 逐个资产 sha256；目标用分支名（踩坑 53）；下载回来逐个核对 |
| 精读另加 | 切句 → 生词标注 + 翻译 → 独立复核 → 修正 → 原音逐句切段（长等待压到 2 秒）→ 分屏 → 截图（只看新情况）→ 视频 | 标注 / 复核：模型；其余 Actions（照用 `render-cet6-chalk.yml` 的六级黑板流水线） | 踩坑 14：复核通过前不出视频；铁律 1 每句至少一个生词；layoutcheck、split_check、预检 `--preflight` |

**引擎复用**：练习视频的 `六级/听力/tools/听力视频.py` 直接导入专八引擎（`专八/听力/tools/听力视频.py`），排版检查、字体检查、彩色检查、截图、编码、成品核查一律调用专八那份（规则只写一处）。只写六级自己的两块：时间轴锚点，以及画面（六级没有填空答题卡，只有选项）。字体用专八取出的同一套原卷 Times New Roman（`取字体.py`）。

**六级与专八的题型差异**（只影响画面和锚点）：

| | 专八 2025 | 六级 |
|---|---|---|
| 结构 | A 讲座填空 10 空 + B 采访两段 10 题 | A 长对话 2 段（4+4 题）、B 短文 2 篇（3+4 题）、C 讲座 3 段（3+3+4 题），共 25 题 |
| 卷面 | 答题卡（填空）+ 选项 | 只有选项，不印题干 |
| 预览 / 检查时间 | 预览 30 秒、检查 3 分钟 | 没有；每题后停顿约 15 秒 |
| 画面 | 说明 → 答题卡 → 选项一览 → 逐题 | 说明 → 本段选项一览（播放中）→ 逐题（题干 + 4 个选项 + 作答倒计时）→ 下一段；末尾参考答案两屏（1—15、16—25） |

## 二、本项目会碰到的坑和防法
- **14**：精读先标注、翻译复核、修正，再出音频和视频。
- **30 / 36**：先样片（最难的一套走完全程，全部检查 0 处），截图先审后出视频。批量中绝不改生成程序。
- **43 / 52**：zip 一律用 Python zipfile，中文名按 UTF-8 标记，没有就按 GBK 解。
- **48**：本机配额只剩约 6 GB，所以重活全放 Actions，本机只留文本和 json。原始大文件只在 Release 上。
- **49 / 51**：每段产物落盘即提交；长等待期间挂后台等待任务 + `send_later` 自查。
- **53**：Release 目标一律用分支名（`check-release-target.py`）。
- **68 / 84**：新工作流由专八和六级黑板的工作流复制而来，推送前比对步骤数，并按工作流的检出路径在本机试排一套。
- **77**：锚点唯一、递增；答案泄露检查；倒计时按实测停顿。六级的答案是字母，泄露检查改为：考试画面不许出现“答案 / KEY”，选项不许带任何标记。
- **78**：浏览器版本本机与 Actions 一致（`check-browser-match.py`，用 153）。
- **86**：视频与音频绑定。成品 meta 写原音 sha256，必须等于 `SHA256SUMS`。
- **98—100**：机器被收回时自动重跑一次；收结果按完整性判断，30 套齐了才发布。
- **原音不适用 TTS 那几条检查**（句间 0.8 秒、逐句响度、电磁音、合格证）：理由照专八听力，写在引擎注释里；只做整体增益，峰值 ≤ −1 dBFS。

## 三、只能模型看的，压到最小
1. **文本定稿的待核处**：三方都对不上的地方（预计每套几处到十几处，多是人名、数字），只看这几处的上下文，不通读。
2. **截图**：样片那一套每种屏各看一张（约 10 张），批量只靠程序检查。
3. **精读的标注 + 翻译 + 复核**：这是程序做不了、必须模型做的大头，30 套约 7,000 句。复核按铁律 14：一个审阅员 + 埋雷。

## 四、token 估算
| 段 | 估算 |
|---|---|
| 设计、引擎改写、样片（本会话） | 约 15 万 |
| 30 套文本待核 | 约 5 万 |
| 30 套练习视频批量（Actions，不花 token） | 约 1 万（只看结果） |
| 精读：标注 + 翻译（30 套 × 约 230 句） | 约 150—200 万（子代理并行，每个 ≤ 30 万） |
| 精读：复核（一个审阅员 + 埋雷） | 约 60—80 万 |

**精读是 token 大头**。练习视频 30 个做完、发布之后再开精读，先用一套试，量出真实消耗再定规模。

## 五、断了怎么接
每段产物都按套落盘，在 `六级/听力/<套>/` 下提交推送。重跑时，已完成且指纹相同的套自动跳过。Actions 的结果直接提交，不依赖本容器醒着。长任务设 `send_later` 自查。

## 六、顺序
1. 清点（已完成）
2. Actions 识别 + OCR（30 套）
3. 文本定稿 + 题目答案（程序）
4. 样片：先做一套（开头说明 + Section A 第一段对话 + 第 1—4 题），1080p 发给老师。等回音期间接着做 30 套的文本定稿；60 分钟没有意见就开批量。
5. 30 套练习视频（Actions）
6. 发布
7. 精读：先一套试，再分批
